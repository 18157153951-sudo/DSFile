# 构建与安装

本文覆盖：本地怎么编、CI 怎么出包、为什么是未签名 IPA、怎么重签安装、怎么改名换图标、怎么升级内嵌的 DarkSword 代码。

事实来源：`DSFile/project.yml`、`.github/workflows/build-app.yml`、`DSFile/Sources/Core/BuildInfo.swift`、`DSFile/Vendor/Escape/NOTICE.md`。

---

## 一、本地构建需要什么

| 依赖 | 说明 |
| --- | --- |
| macOS | Xcode 及其命令行工具只能在 macOS 上跑（CI 用的也是 `macos-latest`）。 |
| Xcode | 需要能编 iOS 15 + arm64 的 Xcode。仓库里**没有** `.xcodeproj`（`.gitignore` 明确忽略了 `DSFile/DSFile.xcodeproj/`），工程是现场生成的。 |
| XcodeGen | 用 `project.yml` 生成 `.xcodeproj`。CI 里是 `brew install xcodegen`。 |

### 三条命令

```bash
# 1. 装 XcodeGen（只需要一次）
brew install xcodegen

# 2. 生成 Xcode 工程（必须在 DSFile/ 目录里执行，project.yml 在这一层）
cd DSFile && xcodegen generate

# 3. 编译（参数照抄 CI，产物不进 Xcode 的 DerivedData，直接落 build/Release-iphoneos）
cd DSFile && xcodebuild build \
  -project DSFile.xcodeproj \
  -target DSFile \
  -configuration Release \
  -sdk iphoneos \
  CONFIGURATION_BUILD_DIR="$PWD/build/Release-iphoneos" \
  CODE_SIGNING_ALLOWED=NO \
  CODE_SIGNING_REQUIRED=NO \
  CODE_SIGN_IDENTITY="" \
  COPY_PHASE_STRIP=NO \
  STRIP_INSTALLED_PRODUCT=NO
```

编完的产物：`DSFile/build/Release-iphoneos/DSFile.app`（可执行文件是 `DSFile.app/DSFile`）。

> 真正跑起来还需要第 2 步之外的「打上构建标记」。CI 会做一次（见下一节第 3 步），本地想带上标记也可以手动改 `DSFile/Sources/Core/BuildInfo.swift` 里 `static let stamp = "dev"` 那一行。不改也能编，只是设置页显示的构建标记是 `dev`。

### 本地自己打一个未签名 IPA

```bash
cd DSFile
rm -rf Payload DSFile.ipa
mkdir -p Payload
cp -R build/Release-iphoneos/DSFile.app Payload/
zip -qry DSFile.ipa Payload
ls -lh DSFile.ipa
shasum -a 256 DSFile.ipa
```

（这就是 CI 里「打包未签名 IPA」那一步做的事。）

### 想用 Xcode 图形界面打开

```bash
cd DSFile && xcodegen generate && open DSFile.xcodeproj
```

打开后如果要真机跑，注意 `project.yml` 里把签名全关了（`CODE_SIGN_IDENTITY: ""`、`CODE_SIGNING_REQUIRED: NO`、`CODE_SIGNING_ALLOWED: NO`）——想在 Xcode 里直接装到设备，得在 target 的 Signing & Capabilities 里自己选 Team 并打开自动签名；不过那属于本地调试，不是本仓库的发布路径。

## 二、用 GitHub Actions 出包

工作流文件：`.github/workflows/build-app.yml`（名字就是 Actions 列表里显示的 `Build App`）。

### 触发条件

| 事件 | 条件 |
| --- | --- |
| `push` 到 `main` 或 `master` | 且改动路径匹配 `DSFile/**` 或 `.github/workflows/build-app.yml` |
| `pull_request` | 且改动路径匹配 `DSFile/**` |
| `workflow_dispatch` | **可以手动触发**：仓库 → Actions → 左侧选 `Build App` → 右上「Run workflow」 |

> 权限是 `contents: read`，只读仓库，不涉及任何 secret。

### 每一步做什么

| 步骤 | 命令/动作 | 说明 |
| --- | --- | --- |
| 1 | `actions/checkout@v4` | 拉代码 |
| 2 | `brew install xcodegen` | 装 XcodeGen |
| 3 | `xcodegen generate`（工作目录 `DSFile`） | 从 `project.yml` 生成工程 |
| 4 | 打上构建标记 | 把 `Sources/Core/BuildInfo.swift` 里的 `static let stamp = "dev"` 替换成 `<短 commit> · <月-日 时:分>`，然后 `cat` 出来 |
| 5 | `xcodebuild build ...` | Release / iphoneos / 不签名（参数同上文第三节） |
| 6 | **nm 符号校验** | 见下 |
| 7 | 打包未签名 IPA | `Payload/` + `zip -qry DSFile.ipa Payload`，并打印 SHA256 |
| 8 | `actions/upload-artifact@v4` | 上传 artifact，名字 **`DSFile-ipa`**，找不到文件就失败（`if-no-files-found: error`），保留 **30 天** |

第 6 步的校验逻辑（原文意图）：

```bash
BIN=build/Release-iphoneos/DSFile.app/DSFile
for SYMBOL in kexploit_opa334 sandbox_escape; do
  if nm -a "$BIN" | grep -q "$SYMBOL"; then
    echo "✅ 找到符号 $SYMBOL"
  else
    echo "❌ 二进制里没有 $SYMBOL —— 内核逃逸代码没编进去，装上去也是白装"
    exit 1
  fi
done
lipo -info "$BIN"
```

**这一步的意义**：C 代码如果只被声明没被引用，链接器可能把它优化掉；如果 `kexploit_opa334` 或 `sandbox_escape` 符号不在最终二进制里，说明内嵌的逃逸代码根本没链进去——那样编出来的 App 装上也是白装（激活必然失败）。CI 直接让它构建失败，避免你下载到一个「看起来正常但不能用」的 IPA。同时 `lipo -info` 打印架构，确认是 arm64。

顺带一提：Release 配置里刻意带了 `COPY_PHASE_STRIP=NO` 和 `STRIP_INSTALLED_PRODUCT=NO`，就是为了别把符号 strip 掉，让第 6 步和 `nm` 校验有意义。

### 下载 artifact

Actions → 那次运行 → 页面底部 **Artifacts** → 点 `DSFile-ipa` 下载 zip → 解压得到 `DSFile.ipa`。

## 三、为什么出的是未签名 IPA / 怎么装

### 为什么

- CI 上没有、也不该有你的签名证书；`project.yml` 把签名相关设置全部关掉了：
  ```yaml
  CODE_SIGN_IDENTITY: ""
  CODE_SIGNING_REQUIRED: NO
  CODE_SIGNING_ALLOWED: NO
  ```
- 这样产物是一个「裸的、已编译好的 App 包」，签名交给**你自己的证书**在本地完成。好处是你不需要把证书交给任何人（包括这个仓库）。

### 怎么重签安装

用 **eSign / 轻松签** 这类工具（Sideloadly、AltStore、TrollStore 等同类工具同理）：

1. 把 `DSFile.ipa` 传到手机上（AirDrop / 文件 App / 云盘都行）；
2. 打开 eSign / 轻松签 → 选这个 IPA → 选择你自己的签名（个人开发者证书 / 企业证书 / 已导入的 p12）；
3. 重签 → 安装；
4. 如果工具里能找到「注入 entitlements / 自定义权限」之类的高级选项，**保持默认，不要加**。

### entitlements 为什么要留空

要在重签时注入的私有权限，比如 `platform-application`、`com.apple.private.*`、`no-sandbox` 等等：

- **没必要**：本 App 拿到整机读写靠的是运行时内核读写 + 改写本进程沙盒数据（见 [内核与风险.md](内核与风险.md)），完全不走 entitlements 这条路；
- **有副作用**：带私有权限的签名在别的系统版本/面板上经常出问题——装上打不开、被系统直接杀掉、或者签名工具/系统面板不认这个描述文件；
- 所以 `project.yml` 里也没有任何 entitlements 文件，重签时也请你别加。

`project.yml` 里唯一和「系统会问你什么」相关的设置是 `ITSAppUsesNonExemptEncryption: false`（声明不使用非豁免加密），以及 `UIFileSharingEnabled` + `LSSupportsOpeningDocumentsInPlace`（让 App 自己的 Documents 在系统「文件」App 里可见、方便导入脚本和导出日志）。这两个都是正常 App 的公开设置，不涉及私有权限。

## 四、改 App 名字 / bundle id / 图标

全部在 `DSFile/project.yml` 里改。

### 显示名（桌面图标下面那行字）

```yaml
    info:
      properties:
        CFBundleDisplayName: 暗剑文件      # ← 改这里
        CFBundleName: DSFile
```

### bundle id

```yaml
options:
  bundleIdPrefix: com.dsfile              # ← 只影响「没显式写 id 的 target」的默认前缀
...
      base:
        PRODUCT_BUNDLE_IDENTIFIER: com.dsfile.app   # ← 这才是最终 bundle id
```

改 `PRODUCT_BUNDLE_IDENTIFIER` 时注意：换 bundle id 等于换了一个 App，设备上会**并存安装**（旧的那份数据不会跟过来）。

### 可执行文件名 / 产品名

```yaml
        PRODUCT_NAME: DSFile              # ← 产物是 DSFile.app，可执行文件叫 DSFile
```

改了 `PRODUCT_NAME`，CI 里的路径也要跟着改（`.github/workflows/build-app.yml` 里的 `build/Release-iphoneos/DSFile.app/DSFile`、`Payload/DSFile.app`）。一般**不建议改**。

### 版本号

```yaml
        MARKETING_VERSION: "0.1.0"        # ← 对外版本
        CURRENT_PROJECT_VERSION: "1"      # ← Build 号
```

> 设置页「关于」里显示的 `0.1.0（Build 1）` 是 `SettingsView.swift` 里写死的常量，**不会**跟着 `project.yml` 自动变；改了版本号想同步显示，得同时改那两个常量（`appVersion` / `appBuild`）。

### 图标

```
DSFile/Sources/Assets.xcassets/
├── Contents.json
└── AppIcon.appiconset/
    ├── Contents.json
    └── icon1024.png
```

- 现在只有一张 `icon1024.png`；`project.yml` 里通过 `ASSETCATALOG_COMPILER_APPICON_NAME: AppIcon` 指定资源名。
- 换图标：**直接替换 `icon1024.png`**（保持 1024×1024 的 PNG），或者往 `AppIcon.appiconset/` 里加你需要的尺寸，并在该目录的 `Contents.json` 里登记——加尺寸时以 `Contents.json` 现有的字段结构为准。
- 换完重新 `xcodegen generate` + 编译。

## 五、升级内嵌的 DarkSword 代码

`DSFile/Vendor/Escape/` 里的 C / Objective-C 代码**不是本项目原创**，是把公开的 DarkSword 沙盒逃逸实现搬进来内嵌使用的。完整来源、作者、许可状态和「相对上游做了哪些改动」，请以 **[DSFile/Vendor/Escape/NOTICE.md](../DSFile/Vendor/Escape/NOTICE.md)** 为准（这是唯一的权威说明，本文只做导航）。

### 现状速览

| 上游文件 | 本仓库位置 | 作者/来源 |
| --- | --- | --- |
| `kexploit/*`（`kexploit_opa334` / `krw` / `kutils` / `offsets` / `vnode` / `machine_info` / `xpaci`） | `Vendor/Escape/kexploit/` | wh1te4ever、opa334（经 34306/FilzaJailedDS） |
| `sandbox_escape.{h,m}` | `Vendor/Escape/` | CrazyMind90、rooootdev、34306 |
| `apfs_own.{h,m}` | `Vendor/Escape/` | rooootdev、34306 |
| `utils/*` | `Vendor/Escape/utils/` | 34306 |
| `Shims/`（`sys/fileport.h`、`IOSurface/IOSurfaceRef.h`、`DSIOShim.c`） | `Vendor/Escape/Shims/` | **本项目新增**，不是上游内容 |

上游**没有附带开源许可证**。仓库里的这份副本仅用于「在你自己的设备上自行构建、自行安装」，不随任何公开分发。要再分发，先联系上游作者取得许可，或者把 `Vendor/Escape` 换成你自己实现的等价模块。

### 相对上游删掉了什么

1. `Tweak.m`（给 Filza 做注入用的 hooks，DSFile 不需要）；
2. `kpf/`、`XPF/`、`ChOma`（`xpf_*` / `grab_kernelcache` 在这条逃逸路径上并没有被调用，删掉可以明显降低编译面和二进制体积）。

**逃逸 / 内核读写逻辑本身没有被改动。**

### 升级步骤（换上游代码）

1. 从上游仓库取新版本的对应文件；
2. **保持 NOTICE.md 里列出的裁剪**：不要带回 `Tweak.m`、`kpf/`、`XPF/`、`ChOma`；`Shims/` 是我们自己的兼容层，升级时不要被上游文件覆盖掉，但要注意上游结构体/函数签名变化时可能要同步调整 `Shims/sys/fileport.h`、`Shims/IOSurface/IOSurfaceRef.h`、`Shims/DSIOShim.c`；
3. 上游如果改了 `DSKernel.m` 依赖的符号名，需要同步改 `Sources/Core/DSKernel.m` 的 `#import` 与调用（当前它依赖 `kexploit_opa334()`、`proc_self()`、`sandbox_escape()`、`sandbox_elevate_to_root()`、`apfs_own()`、`apfs_own_tree()`、`apfs_mod()` 以及全局 `g_kernel_base`）；
4. 编译前确认 `HEADER_SEARCH_PATHS` / `OTHER_CFLAGS` 依旧覆盖 `Vendor/Escape/Shims`、`Vendor/Escape`、`Sources/Core`（`project.yml` 里已经配好，新增子目录要记得加）；
5. **跑一次 CI 的 nm 校验**（`kexploit_opa334`、`sandbox_escape` 两个符号必须存在）；
6. 更新 `Vendor/Escape/NOTICE.md`：写清新的来源、日期、以及这次相对上游又改了哪些地方——这份文件是后续维护者唯一的依据，别省。

### 什么时候必须升级

- 你的系统版本/机型不在当前 `offsets.m` 的覆盖区间里（激活会报「内核漏洞执行失败，通常是机型/系统版本不在 offset 表内」）；
- 上游新增了对新版本 iOS 或新芯片的 offset。

> 提醒：`offsets_init()` 在版本不满足 `17.0 <= 版本 < 26.1` 时会直接 `printf` 一行再 `exit(EXIT_FAILURE)`。App 侧的 `KernelCenter.activate()` 会先做版本判定、根本不会走到那一步；但如果你手动改了什么去绕过，这个 `exit` 会让 App 直接退出——以源码为准。
