# 注入 3105：把 myfilza 的「替换」能力装进 3105

> 产物：`MyfilzaReplace.dylib`（由 `InjectDylib/` 编出，CI workflow `Build Inject Dylib`）
> 思路：**像当初魔改 Filza 一样做 dylib 注入**，只是这次注入进 3105。

## 为什么这条路最稳

3105 本体在你的 iPhone13,4 / iOS 18.5 上**本来就能访问其它 App 的数据容器**。
把我们的替换向导注入进去后，我们的代码运行在**已经有文件访问权限的宿主进程里**，于是：

| | 需要什么 |
| --- | --- |
| 内核漏洞 | **不需要** → 没有内核 panic / 重启风险 |
| 沙盒逃逸（改 label / ext_set） | **不需要** |
| 我们的文件操作 | 直接 POSIX 读写（`DSKernel` 替身只做探测 + `chown`/`chmod`） |

也就是说：**稳定性来自"不碰内核"**，而不是"把内核漏洞调得更稳"。

## 一、注入步骤

先确认你有：**3105 的 IPA**（可重签的那种，不是 App Store 版）+ 自己的签名证书。

### 方案 A：eSign（纯手机，推荐）

1. 把 `MyfilzaReplace.dylib` 和 3105 的 IPA 一起放进「文件」App（或 eSign 的导入目录）；
2. eSign → 「签名」→ 选择 3105 的 IPA；
3. 在签名设置里找到「**注入 dylib / 注入动态库**」，选择 `MyfilzaReplace.dylib`；
4. 用你的证书签名，然后安装；
5. 打开 3105：约 1.5 秒后屏幕上会出现一个蓝色圆形悬浮按钮「**替换**」。

### 方案 B：Sideloadly（电脑）

1. 电脑上打开 Sideloadly，`IPA` 选 3105 的 IPA；
2. 展开 `Advanced Options` → `Inject dylibs/frameworks` → 选 `MyfilzaReplace.dylib`；
3. 用你的 Apple ID / 证书签名并安装到设备。

> 两个方案本质一样：往宿主主二进制的加载命令里加一条指向我们 dylib 的记录，再把 dylib 放进
> `Payload/<宿主>.app/Frameworks/` 并一起重签。

## 二、注入后怎么用

1. 打开 3105 → 等悬浮按钮出现（若没出现，见下面「排查」）；
2. **点按钮** → 弹出「myfilza 替换」向导（与 myfilza App 里**完全同一套**逻辑）：
   - **目标 App**：选一个已安装 App（宿主能读到容器，所以列表能出来）；
   - **添加目标文件 / 文件夹（浏览 …）**：在目标 App 的**数据容器**或 `.app` 包体里挑文件（可多选；点文件夹进入；右上角「确定」= 有选中就提交选中项、没选中就提交当前目录；长按文件夹 = 选为文件夹目标）；
   - 选中项会**自动在本机按同名配替换源**：唯一命中自动绑定；多个让你选；没有就弹本机选择器；
   - **多出来的文件**：`保留`（默认，只覆盖同名）/ `删除`（让目标与源一致）；
   - **预演**（只看不动）→ **开始替换**（替换前自动整份备份）；
   - **一键回滚**：结果卡片里、或「最近的替换」里、或记录页里，都是同一个回滚实现。
3. **拖动**按钮可移动位置；**长按**按钮切换最小化（半透明小圆点），再长按恢复；位置与最小化状态都会记住。

## 三、数据存在哪

全部写在**宿主 App（3105）自己的沙盒**里：

| 路径（相对宿主 Home） | 内容 |
| --- | --- |
| `Documents/Backups/<时间戳>-<名字>/` | 备份会话（`manifest.json` + `files/`） |
| `Documents/Runs/` | 运行记录（`.json` + `.log`） |
| `Documents/AutoTasks/` | 自动化任务（保存的绑定，手动运行） |
| `Documents/ReplaceSources/` | 导入的替换源（本机文件 / 文件夹） |
| `Documents/ImportInbox/` | 选择器导入的中转目录 |
| `Documents/Logs/myfilza-inject.log` | **注入版自己的日志**（悬浮按钮挂载、打开向导、回滚等） |

出问题时把 `Documents/Logs/myfilza-inject.log` 发出来即可定位（每行都 fsync，宿主被杀也留得住）。

## 四、已知限制

1. **宿主版本差异**：3105 升级后 UI/类名可能变化；我们**不调用任何 3105 的函数**，只往它的
   key window 上挂按钮、并用 POSIX 读写文件，所以一般不受影响；万一按钮挂不上，看日志里
   「等待 key window 超时」那行。
2. **Swift 运行时**：dylib 用 CI 上的 Xcode 编译，会依赖宿主提供的 Swift 运行时。3105 本身是
   Swift App，所以运行时一定存在；但如果宿主是用**更老的** Xcode 构建的，理论上可能缺符号
   （表现为打开就崩）。真遇到就换用与宿主同版本的 Xcode 重新构建本 dylib。
3. **`/System`、`/usr`** 仍是只读（SSV 签名卷），任何工具都改不了 —— 与内核方案无关，是系统限制。
4. **提权不可用**：注入版没有内核读写，只能用宿主进程的身份（通常 uid=501）。向导里点「提权」会明确报失败，不影响替换功能。
5. **改自签 App 的包体**会破坏它的签名校验，可能让它打不开（有备份可回滚，必要时重装）。
6. **GPL-3.0**：本仓库内含 3105 的源码（`DSFile/Vendor/ThreeOneOSFive/`），因此再分发按 GPL-3.0 对待；
   本 dylib 只是把**我们自己的**代码编成库，不包含 3105 的代码。

## 五、排查

| 现象 | 先看什么 |
| --- | --- |
| 打开 3105 没有悬浮按钮 | `Documents/Logs/myfilza-inject.log`：有没有「悬浮按钮已挂载」/「等待 key window 超时」 |
| 点按钮没反应 / 立刻消失 | 日志里「当前已有 sheet 在展示，先关闭再打开」→ 先关掉宿主的其它弹窗再点 |
| 向导里 App 列表为空 | 说明宿主此刻没有容器访问权限：先用 3105 自己的功能确认它能浏览别的 App 数据 |
| 替换失败 | 向导里的日志区会写明是哪一步（绑定 / 源文件 / 权限 / 备份） |
