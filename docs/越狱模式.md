# 越狱模式（0.9.2）

> 面向：**已越狱设备**（roothide / rootless（`/var/jb`）/ 经典越狱）。
> 免越狱设备请继续用「内核模式」（见 `docs/内核与风险.md`）。

## 一、为什么要有「越狱模式」

免越狱时，文件访问必须靠内核漏洞 + 沙盒逃逸；但在越狱设备上，**越狱 App 本来就没有沙盒**，
直接用 POSIX 就能读写系统路径 —— 这时再跑内核漏洞既没必要、又白白增加崩溃风险。

所以 0.9.0 在设置页「访问路径」里加了第四项：**仅越狱（直接 POSIX，不跑漏洞）**。

## 二、为什么 TrollStore 安装的 App 在 roothide 下没权限（真机结论）

真机：**iPad13,4 / iOS 16.4.1 / roothide 越狱**，用 **TrollStore** 安装本 App，日志为：

```
[MHA 诊断] TeamIdentifier = TROLLTROLL；application-identifier = TROLLTROLL.*      ← TrollStore 实锤
AppScanner: 0 个 App（LSApplicationWorkspace=0，容器扫描=0，文件系统访问=否，未检测到越狱特征）
```

**根因**：roothide 的设计目标就是**对 App 隐藏越狱** —— 它把越狱根放在一个**随机命名的 jbroot** 里，
并且**不给普通 App 越狱权限**。TrollStore 安装的 App 属于"普通 App"，因此：

- 看不到 `/var/jb`、看不到 `.jbroot`、环境变量也没有；
- 即使签名是 TrollStore（`TROLLTROLL`），也**不会**获得 `platform-application` 之类的沙盒例外；
- 结果就是：**能装、能启动、但读不到系统路径**。

要让 App 真正读写全盘，只有一条路：**以越狱 App 方式安装**（装进 `<jbroot>/Applications/`，带沙盒例外）
—— 也就是用 Sileo / Zebra 装 `.deb`。

## 三、怎么用（两条安装路，任选一条）

> **0.9.1 起越狱版是独立的 App**：bundle id = `com.dsfile.app.jb`，显示名 `myfilza JB`。
> 侧载版仍是 `com.dsfile.app`，显示名 `myfilza` —— 两者**可以共存**（数据容器各自独立），
> 但为了不混淆，建议**先卸载侧载版再装越狱版**。

**路线 A：Sileo / Zebra 装 deb（首选）**

1. 从 CI 产物里拿到 `myfilza_0.9.2_iphoneos-arm64e.deb`（workflow `Build Jailbreak Deb`；
   另有 `iphoneos-arm64` 变体给非 arm64e 设备兜底）；
2. 用 **Sileo / Zebra** 安装它 → 桌面出现 **`myfilza JB`**；
3. 打开 App → 设置 → 「访问路径」选 **仅越狱**（或保持「自动」，它会先试越狱模式）→ 点激活。

**路线 B：手动安装包 `myfilza-jb-manual.zip`（deb 装不上时用）**

真机上 deb 可能报 `dpkg: error creating directory "./rootfs/Applications/myfilza.app":
Read-only file system` —— 那是 dpkg 把包当成"要写真实 rootfs（只读）"了（原因见第十节）。
这时改用手动包，**不经过 dpkg**：

1. 解压 `myfilza-jb-manual.zip`（内含 `myfilza.app`、`entitlements.plist`、`install.sh`、`README.txt`）；
2. 把这三样放同一个目录，在**越狱环境的终端**（SSH 或设备上的终端 App）里执行：
   ```sh
   cd 该目录
   sh install.sh
   ```
   脚本会：定位越狱根（`jbroot` 命令 → 环境变量 → **`.jbroot` 符号链接** → 扫描 `.jbroot-*` → `/var/jb`，
   并校验 `<root>/usr` 或 `<root>/bin` 存在才采用）→ 复制到 `<jbroot>/Applications/` →
   `ldid` 注入 entitlements → `uicache` 刷新 → 逐条校验并打印结果。**幂等，可重复运行**。
   需要 bootstrap 里已有 `ldid` 与 `uicache`（一般都有；缺了脚本会提示怎么装）。

怎么确认自己打开的是哪一个：设置 →「关于 → 版本形态」会直接写
`越狱版(.deb)` / `侧载版` / `MHA 变体`，并附 bundle id 原文；启动日志第一行同样有这一段：

```
[启动] myfilza 0.9.2 (build …) 启动：iPad13,4 / iOS 16.4.1 / A14 / M1 · 版本形态 = 越狱版(.deb)（bundle id = com.dsfile.app.jb）
```

装好后日志里应该能看到：

```
[myfilza] 越狱模式：**不执行任何漏洞**，直接用越狱环境给的 POSIX 权限
[越狱诊断] ② 本 App 容器/包体内的 .jbroot 标记 … 找到标记 …/App.app/.jbroot → 符号链接指向 <jbroot> ✓
[越狱诊断]   · platform-application = true
[越狱诊断]   · com.apple.private.security.container-required = false
[myfilza] ✅ 本次实际路径 = 越狱 · 直接 POSIX（可读写）
```

## 四、jbroot 是怎么解析的（按 roothide 官方文档）

roothide 官方文档 `roothide/Developer/roothide.md` 原文：

- *"roothide ... (re)installs the jailbreak to a directory(named jbroot) with a random name each time we jailbreak."*
- *"each directory containing a mach-o file will automatically generate a `.jbroot` symbolic link that pointing to
  the jailbreak root directory, it's usually generated by **dpkg when installing packages**, or generated by the
  jailbreak itself when loading a binary/library"*
- *"roothide's bootstrap uses jbroot as the default root"* —— 所以包内路径按 jbroot 相对写。

因此本 App 的解析顺序（**逐条尝试，每条结果都写进日志**）：

| 顺序 | 依据 | 说明 |
| --- | --- | --- |
| ① | `getenv("JBROOT")` / `getenv("ROOTHIDE")` | 被越狱环境注入时最直接 |
| ② | **本 App 自己容器 / 包体内的 `.jbroot` 标记** | 沙盒内看不到真正的越狱目录，只能靠自己包里的这个符号链接 —— **越狱版 deb 装完 dpkg 就会生成它** |
| ③ | `/var/mobile/Library/roothide` + 可见的 `.jbroot*` | roothide 环境标志 |
| ④ | `/var/jb` | rootless（Dopamine / palera1n rootless） |

> 注意：本 App **不链接** `libroothide`（那需要被 roothide 打补丁才行），所以走的是上面这套
> "沙盒内也能用"的信号；这也意味着**没装越狱版 deb 时解析不到 jbroot 是正常的**。

## 五、entitlements 诊断：判断"权限没给"还是"沙盒在拦"

设置页「环境 → 探测细节」会列出本 App 自己的：

```
platform-application
com.apple.private.security.container-required
com.apple.private.security.no-sandbox
com.apple.private.security.storage.AppBundles
com.apple.private.security.storage.AppDataContainers
get-task-allow
task_for_pid-allow
application-identifier
com.apple.developer.team-identifier
```

> 其中前四项是 roothide 官方 `entitlements.md` 给越狱二进制列的基础四件套
> （`storage.AppBundles` 与 `storage.AppDataContainers` 正是"读写 App 包体 / 数据容器"要用的，
> 0.9.1 及以前我们漏了这两个 —— 0.9.2 起 deb 与手动包都按四件套签名）。

判断规则：

| 现象 | 结论 |
| --- | --- |
| `platform-application` 或 `storage.AppDataContainers` 缺失 | **权限没给** → 用越狱版 `.deb` 或手动包安装（TrollStore 装出来的就是这样） |
| 四件套都在，但探针仍是 `EPERM(沙盒拒绝)` | 越狱环境在拦（少见）→ 检查是否真的装进了 `<jbroot>/Applications/` |
| 探针成功 | 越狱模式可用，直接读写系统路径 |

逐路径探针（`DSFSAccessProbe`）会给出每个路径的真实 `errno`：
`EPERM(1)=沙盒拒绝`、`EACCES(13)=权限不足`、`ENOENT(2)=不存在`、`EROFS(30)=只读文件系统`。

## 六、和内核模式的区别

| | 越狱模式 | 内核模式（FilzaJailedDS / 3105） |
| --- | --- | --- |
| 是否执行漏洞 | **否**（零漏洞、零 panic 风险） | 是 |
| 前提 | 必须是**越狱 App**（装进 `<jbroot>/Applications/`） | 系统在漏洞覆盖范围内（如 17.0–26.0.x） |
| 失败时 | 明确失败并说明原因，**不回退内核** | 依赖漏洞 race，可能失败（重启 App 重试） |
| 适用 | 越狱设备（roothide / rootless / 经典） | 免越狱设备，或越狱设备上懒得装 deb 时 |

## 七、越狱版 `.deb` 是怎么打出来的（CI：`Build Jailbreak Deb`）

1. 与 IPA 同一套编译流程产出 `myfilza.app`（不签名）；
2. `ldid -S jailbreak/entitlements.plist myfilza.app/myfilza` 注入 **roothide 官方四件套**
   （`platform-application`、`com.apple.private.security.no-sandbox`、
   `com.apple.private.security.storage.AppBundles`、`com.apple.private.security.storage.AppDataContainers`
   —— 后两个正是"读写 App 包体 / 数据容器"要用的，0.9.1 及以前漏了）
   + `container-required=false` + `get-task-allow`；**并逐条校验签名里确实带上**（否则 CI 失败）；
3. 显示名改成 `myfilza JB`、**bundle id 改成 `com.dsfile.app.jb`**
   （0.9.0 时两版共用 `com.dsfile.app`，装上去互相顶 —— 0.9.1 起越狱版独立，
   且 CI 会自检「bundle id 必须是 `.jb`、显示名必须是 `myfilza JB`」，否则构建失败）；
4. `data.tar` 布局 `./Applications/myfilza.app/...`（roothide 的 bootstrap 以 jbroot 为根 →
   装完即 `<jbroot>/Applications/myfilza.app`）；
5. `DEBIAN/control`：`Package: com.dsfile.myfilza`、
   **`Architecture: iphoneos-arm64e`**（真实 roothide 包一律是这个值；另出一份 `iphoneos-arm64` 兜底）、
   `Depends: firmware (>= 15.0)`；
6. `DEBIAN/postinst`：**在设备上再用 `ldid` 重新签名一次**（entitlements 内联在脚本里，ldid 是 bootstrap 自带的），
   然后 `uicache -a`（回退 `uicache -p /Applications/myfilza.app`）—— 真实 roothide 包也这么做
   （例如 `CrossOverIPC_Roothide.deb` 的 postinst 就是 `ldid -s`）；
7. `dpkg-deb --build --root-owner-group` 打包，并**自检三条**：`Architecture` 字段与文件名一致、
   文件清单含 `Applications/myfilza.app/myfilza`、**路径里不允许出现 `rootfs/`**
   （出现就说明会被当成写真实 rootfs —— 正是真机报错的原因）。

## 八、三个版本形态的区别（侧载版 / MHA 变体 / 越狱版）

同一个 myfilza 会产出三种包，**它们看起来一模一样，只有 bundle id 能区分**，
所以启动日志第一行和设置页「关于 → 版本形态」都会写明：

| 版本形态 | bundle id | 怎么装 | 用途 |
| --- | --- | --- | --- |
| **侧载版** | `com.dsfile.app` | eSign / 证书重签 IPA | 免越狱设备：走内核模式（或 MHA，见 `docs/MHA模式.md`） |
| **MHA 变体** | `com.apple.mobile.MobileHouseArrest` | eSign 重签，**签名 identifier 也要保持这个值** | iOS 26/27 上的零内核容器访问 |
| **越狱版(.deb)** | `com.dsfile.app.jb` | **Sileo / Zebra** 装 `.deb` | 越狱设备：越狱模式，直接 POSIX，不跑漏洞 |

**安装顺序（越狱设备）**：

1. 先卸载侧载版（TrollStore / eSign 装的 `myfilza`）—— 不是必须（bundle id 不同，两者能共存），
   但不卸的话桌面会有两个 myfilza，容易点错、日志也容易看混；
2. 用 Sileo / Zebra 装 `myfilza_0.9.2_iphoneos-arm64e.deb` → 桌面出现 `myfilza JB`
   （装不上就用第十节的手动安装包）；
3. 打开 `myfilza JB` → 设置 →「访问路径」= 仅越狱（或自动）→ 激活。

> 反过来，**越狱版不要用 TrollStore 装**：TrollStore 装出来的是「普通 App」，
> 在 roothide 下没有沙盒例外，越狱模式必然失败（见第二节）。

## 九、已知限制

- 越狱模式**只解决"有没有权限"**；文件操作、替换引擎、备份回滚与免越狱时完全一样（都是 POSIX）；
- roothide 每次重新越狱会换 jbroot 名字，所以 **App 必须在越狱状态下启动**才能解析到（重启后未越狱时解析不到属正常）；
- 越狱版（`com.dsfile.app.jb`）与侧载版（`com.dsfile.app`）是**两个 App**，数据容器各自独立
  —— 越狱版看不到侧载版里的脚本与备份，需要自己重新导入；
- 越狱模式**不做**任何路径翻译：rootless 下就是 `/var/jb/...`，roothide 下用解析出来的 `<jbroot>/...`。

## 十、deb 报 `./rootfs/... Read-only file system` 是怎么回事，以及手动安装包

真机（iPad13,4 / iOS 16.4.1 / roothide）安装 0.9.1 的 deb 时 dpkg 报：

```
Preparing to unpack .../com.dsfile.myfilza_0.9.1_iphoneos-arm64e.deb
Unpacking com.dsfile.myfilza (0.9.1)
dpkg: error processing archive ...:
error creating directory "./rootfs/Applications/myfilza.app": Read-only file system
dpkg-deb: error: paste subprocess was killed by signal (Broken pipe: 13)
```

**为什么**：roothide 官方 `roothide.md` 写明 —— 它把越狱装在随机命名的 **jbroot** 里，
bootstrap 以 jbroot 为根，并且在 jbroot 里放一个名为 **`rootfs`** 的符号链接指向
**iOS 原始根文件系统（只读）**。所以路径里一旦出现 `rootfs/`，就代表"要写真实系统卷"，
必然 `Read-only file system`。0.9.2 因此做了三件事：

1. 架构字段改成真实包一致的 **`iphoneos-arm64e`**（并另出 `iphoneos-arm64`）；
2. data 布局坚持 jbroot 相对（`./Applications/...`），并在 CI 里**断言路径中不出现 `rootfs/`**；
3. 补上官方四件套 entitlements，postinst 在设备上再 `ldid` 签一次。

**如果 deb 仍然装不上**，用**手动安装包 `myfilza-jb-manual.zip`**（完全不经过 dpkg）：

```
myfilza-jb-manual.zip
├── myfilza.app/            越狱版 App（bundle id com.dsfile.app.jb，显示名 myfilza JB）
├── entitlements.plist      roothide 官方四件套 + container-required=false + get-task-allow
├── install.sh              自动安装：定位 jbroot → 复制 → ldid 签名 → uicache → 校验
└── README.txt              中文三步说明 + 失败怎么回报
```

在越狱终端里：

```sh
cd <解压目录>
sh install.sh
```

脚本的关键逻辑（与官方规则一致）：

| 步骤 | 做什么 |
| --- | --- |
| 定位 jbroot | ① `jbroot` 命令 → ② `JBROOT`/`ROOTHIDE` 环境变量 → ③ **`.jbroot` 符号链接**（roothide 官方机制）→ ④ 扫描 `.jbroot-*` → ⑤ `/var/jb`；**并校验 `<root>/usr` 或 `<root>/bin` 存在**才采用 |
| 安装 | `cp -R myfilza.app <jbroot>/Applications/`（幂等：重复运行 = 覆盖安装），`chown -R 0:0` |
| 签名 | `ldid -S entitlements.plist <app>/myfilza`（缺 ldid 会提示怎么装） |
| 刷新 | `uicache -a`（回退 `uicache -p /Applications/myfilza.app`） |
| 校验 | 打印目录与可执行文件权限，并逐条确认 `platform-application` / `storage.AppDataContainers` 在签名里 |

没有终端时也可以用 **Filza** 手动把 `myfilza.app` 放进 `<jbroot>/Applications/`，
但**签名那一步不能省**（否则拿不到沙盒例外），细节见包内 `README.txt`。
