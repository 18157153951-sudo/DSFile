# 越狱模式（0.9.0）

> 面向：**已越狱设备**（roothide / rootless（`/var/jb`）/ 经典越狱）。
> 免越狱设备请继续用「内核模式」（见 `docs/内核与风险.md`）。

## 一、为什么要有「越狱模式」

免越狱时，文件访问必须靠内核漏洞 + 沙盒逃逸；但在越狱设备上，**越狱 App 本来就没有沙盒**，
直接用 POSIX 就能读写系统路径 —— 这时再跑内核漏洞既没必要、又白白增加崩溃风险。

所以 0.9.0 在设置页「访问路径」里加了第四项：**仅越狱（直接 POSIX，不跑漏洞）**。

## 二、为什么 TrollStore 安装的 App 在 roothide 下没权限（真机结论）

真机：**iPad13,4 / iOS 16.4.1 / roothide 越狱**，用 **TrollStore** 安装本 App，日志为：

```
[MHA 诊断] TeamIdentifier = TROLLTROLL；application-identifier = TROLLTROLL.*      ← TrollStore 实锤
AppScanner: 0 个 App（LSApplicationWorkspace=0，容器扫描=0，文件系统访问=否，未检测到越狱特征）
```

**根因**：roothide 的设计目标就是**对 App 隐藏越狱** —— 它把越狱根放在一个**随机命名的 jbroot** 里，
并且**不给普通 App 越狱权限**。TrollStore 安装的 App 属于"普通 App"，因此：

- 看不到 `/var/jb`、看不到 `.jbroot`、环境变量也没有；
- 即使签名是 TrollStore（`TROLLTROLL`），也**不会**获得 `platform-application` 之类的沙盒例外；
- 结果就是：**能装、能启动、但读不到系统路径**。

要让 App 真正读写全盘，只有一条路：**以越狱 App 方式安装**（装进 `<jbroot>/Applications/`，带沙盒例外）
—— 也就是用 Sileo / Zebra 装 `.deb`。

## 三、怎么用（两条命令级步骤）

1. 从 CI 产物里拿到 `myfilza_0.9.0_iphoneos-arm64.deb`（workflow `Build Jailbreak Deb`）；
2. 用 **Sileo / Zebra** 安装它（本地源或直接安装），装完桌面会出现 **`myfilza JB`**；
3. 打开 App → 设置 → 「访问路径」选 **仅越狱**（或保持「自动」，它会先试越狱模式）→ 点激活。

装好后日志里应该能看到：

```
[myfilza] 越狱模式：**不执行任何漏洞**，直接用越狱环境给的 POSIX 权限
[越狱诊断] ② 本 App 容器/包体内的 .jbroot 标记 … 找到标记 …/App.app/.jbroot → 符号链接指向 <jbroot> ✓
[越狱诊断]   · platform-application = true
[越狱诊断]   · com.apple.private.security.container-required = false
[myfilza] ✅ 本次实际路径 = 越狱 · 直接 POSIX（可读写）
```

## 四、jbroot 是怎么解析的（按 roothide 官方文档）

roothide 官方文档 `roothide/Developer/roothide.md` 原文：

- *"roothide ... (re)installs the jailbreak to a directory(named jbroot) with a random name each time we jailbreak."*
- *"each directory containing a mach-o file will automatically generate a `.jbroot` symbolic link that pointing to
  the jailbreak root directory, it's usually generated by **dpkg when installing packages**, or generated by the
  jailbreak itself when loading a binary/library"*
- *"roothide's bootstrap uses jbroot as the default root"* —— 所以包内路径按 jbroot 相对写。

因此本 App 的解析顺序（**逐条尝试，每条结果都写进日志**）：

| 顺序 | 依据 | 说明 |
| --- | --- | --- |
| ① | `getenv("JBROOT")` / `getenv("ROOTHIDE")` | 被越狱环境注入时最直接 |
| ② | **本 App 自己容器 / 包体内的 `.jbroot` 标记** | 沙盒内看不到真正的越狱目录，只能靠自己包里的这个符号链接 —— **越狱版 deb 装完 dpkg 就会生成它** |
| ③ | `/var/mobile/Library/roothide` + 可见的 `.jbroot*` | roothide 环境标志 |
| ④ | `/var/jb` | rootless（Dopamine / palera1n rootless） |

> 注意：本 App **不链接** `libroothide`（那需要被 roothide 打补丁才行），所以走的是上面这套
> "沙盒内也能用"的信号；这也意味着**没装越狱版 deb 时解析不到 jbroot 是正常的**。

## 五、entitlements 诊断：判断"权限没给"还是"沙盒在拦"

设置页「环境 → 探测细节」会列出本 App 自己的：

```
platform-application
com.apple.private.security.container-required
com.apple.private.security.no-sandbox
get-task-allow
task_for_pid-allow
application-identifier
com.apple.developer.team-identifier
```

判断规则：

| 现象 | 结论 |
| --- | --- |
| `platform-application` 缺失 / `container-required` 不是 `false` | **权限没给** → 用越狱版 `.deb` 安装（TrollStore 装出来的就是这样） |
| 两个都在，但探针仍是 `EPERM(沙盒拒绝)` | 越狱环境在拦（少见）→ 检查是否真的装进了 `<jbroot>/Applications/` |
| 探针成功 | 越狱模式可用，直接读写系统路径 |

逐路径探针（`DSFSAccessProbe`）会给出每个路径的真实 `errno`：
`EPERM(1)=沙盒拒绝`、`EACCES(13)=权限不足`、`ENOENT(2)=不存在`、`EROFS(30)=只读文件系统`。

## 六、和内核模式的区别

| | 越狱模式 | 内核模式（FilzaJailedDS / 3105） |
| --- | --- | --- |
| 是否执行漏洞 | **否**（零漏洞、零 panic 风险） | 是 |
| 前提 | 必须是**越狱 App**（装进 `<jbroot>/Applications/`） | 系统在漏洞覆盖范围内（如 17.0–26.0.x） |
| 失败时 | 明确失败并说明原因，**不回退内核** | 依赖漏洞 race，可能失败（重启 App 重试） |
| 适用 | 越狱设备（roothide / rootless / 经典） | 免越狱设备，或越狱设备上懒得装 deb 时 |

## 七、越狱版 `.deb` 是怎么打出来的（CI：`Build Jailbreak Deb`）

1. 与 IPA 同一套编译流程产出 `myfilza.app`（不签名）；
2. `ldid -S entitlements.plist myfilza.app/myfilza` 注入
   `platform-application=true`、`com.apple.private.security.container-required=false`、
   `no-sandbox=true`、`get-task-allow=true`；**并校验签名里确实带上了**（否则 CI 失败）；
3. 显示名改成 `myfilza JB`，方便和侧载版区分（bundle id 仍是 `com.dsfile.app`）；
4. `data.tar` 布局 `./Applications/myfilza.app/...`（roothide 的 bootstrap 以 jbroot 为根 →
   装完即 `<jbroot>/Applications/myfilza.app`）；
5. `DEBIAN/control`：`Package: com.dsfile.myfilza`、`Architecture: iphoneos-arm64`、`Depends: firmware (>= 15.0)`；
6. `DEBIAN/postinst` 调 `uicache -a`（回退 `uicache -p /Applications/myfilza.app`）；
7. 用 `dpkg-deb --build --root-owner-group` 打包（没有 `dpkg-deb` 时回退手工 `ar` +
   `debian-binary` / `control.tar.gz` / `data.tar.gz`），并校验 deb 里确实有
   `Applications/myfilza.app/myfilza`。

## 八、已知限制

- 越狱模式**只解决"有没有权限"**；文件操作、替换引擎、备份回滚与免越狱时完全一样（都是 POSIX）；
- roothide 每次重新越狱会换 jbroot 名字，所以 **App 必须在越狱状态下启动**才能解析到（重启后未越狱时解析不到属正常）；
- 同一个 bundle id 的侧载版与越狱版会同时存在（桌面名分别是 `myfilza` / `myfilza JB`），
  两个 App 的数据容器各自独立；
- 越狱模式**不做**任何路径翻译：rootless 下就是 `/var/jb/...`，roothide 下用解析出来的 `<jbroot>/...`。
