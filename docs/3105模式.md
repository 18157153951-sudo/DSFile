# 3105 模式（第二个内核后端）

> 本文是引入 `github.com/YangJiiii/3105` 作为**可选内核后端**的分析结论、用法与边界。
> 代码逐字节原样放在 `DSFile/Vendor/ThreeOneOSFive/{exploit,kexploit}/`，未做任何修改
> （仅新增一个符号前缀头 `DS3105SymbolPrefix.h`，见下文「隔离做法」）。

---

## 一、3105 的漏洞到底是什么

3105 是**两条腿**：内核漏洞 + 沙盒扩展令牌。两者用途不同。

1. **内核读写**：`kexploit/kexploit_opa334.m` —— 与我们现有后端**同源**（DarkSword / CVE-2025-43520，
   经 opa334 / Dopamine 研究传承，注释里也承认了 FilzaSlop、CrazyMind90、forcequitOS 的贡献）。
   它做的是「竞态 + 物理页越界（OOB）读写」，成功后得到**任意内核读写**。
   - 前置条件：无特殊 entitlement，普通证书签名的 App 即可；**需要真机**（模拟器不可用）。
   - 与我们现有后端的关键差异**不在漏洞本体，而在 offset 表**：3105 的 `offsets.m` 是 49,641 字节，
     覆盖到 iOS 26.x / 27 beta；我们现有的 FilzaJailedDS 2.2 那份是 51,065 字节但只覆盖 17.x–18.x。
2. **沙盒扩展令牌（不是内核漏洞）**：`exploit/bad_query.c` —— 用 ContainerManager（MCM）的
   `container_query` 做**路径穿越**（`part_domain` 传 `../../../../../../../..<路径>`，
   类 13 = `systemgroup.com.apple.mobilegestaltcache`，或类 7 + 指定 group id），
   再 `container_copy_sandbox_token()` 拿到令牌、`sandbox_extension_consume()` 消费它，
   从而**给自己签发任意路径的沙盒扩展**（读写权限）。
   - 这是**纯用户态**的越权：不需要内核漏洞就能拿到沙盒外文件访问。
   - 前置条件：无特殊 entitlement；但只在系统漏洞未被修掉的版本上有效。
   - 另附 `bad_query_list()`：用 `fsgetpath` 按 inode 扫描列出目录（读不到权限时也能列名字）。
3. **3105 自己的策略**（`helpers/KernelExploit.swift` + `SupportPolicy.swift`）：
   `kexploit_opa334()` → `proc_self()` → `sandbox_escape(proc)`；
   **iOS < 26**：拿到内核读写就算「可用」（文件浏览退化为 LSApplicationWorkspace + inode 扫描）；
   **iOS ≥ 26**：必须沙盒逃逸成功（走 bad_query 那条路）。

一句话：**3105 = 同源内核漏洞（更新 offset 表）+ 自己那份 sandbox_escape + bad_query 令牌越权**。

## 二、覆盖范围，以及它补上了我们缺的什么

| | FilzaJailedDS 2.2（默认） | 3105 |
| --- | --- | --- |
| 声明支持 | iOS 17.x – 18.x | **iOS 17.0–17.7.x / 18.0–18.7.1 / 26.0–26.6.1 / 27 beta 1–4**（按 build 白名单：24A5355q、24A5370h、24A5380h、24A5390f） |
| 内核漏洞 | 有（同源） | 有（同源，offset 表更新） |
| 沙盒逃逸 | 我们自己的 cred 路线（`DSCredEscape`） | 它自己的 `sandbox_escape` + `bad_query` |
| 26.x / 27 | ✗ | ✓ |

**引入它的理由**：18.7.1 之后的系统（26.x、27 beta）现有后端完全没有覆盖；3105 是当前能查到的、
声明支持这些版本的公开实现。

## 三、它的文件访问机制 / 文件替换流程

- **内核层**：`kread64/kwrite64` 等原语（`krw.m`）+ `sandbox_escape.m` 改 cred→label→sandbox→ext_set，
  与我们现有思路一致（都源自 FilzaSlop 那套）。
- **令牌层**：`bad_query()` 直接给出沙盒扩展句柄；`mcm_bridge.m` 把 MCM 的
  「枚举标识符 / 取容器路径 / 激活容器路径」包装成 ObjC 接口，供它自己的文件浏览器用。
- **文件替换**：`helpers/FileReplacementService.swift` 只是**在拿到访问权限之后**做常规文件操作
  （读源、写目标、按 patch 事务回滚），**不包含第二套沙盒逃逸**。
  → 所以我们**不需要**照搬它的替换逻辑：本 App 的替换 / 备份 / 回滚继续走我们自己的
  `RecipeRunner` + `RunStore`，3105 只负责「取得文件系统访问」这一件事。

## 四、许可证结论（重要）

- `LICENSE` = **GNU GPL-3.0**（35,149 字节，已核对开头为 "GNU GENERAL PUBLIC LICENSE Version 3"）。
- `THIRD_PARTY_NOTICES.md` 声明：3105 自有部分为 GPL-3.0；同时致谢 FilzaSlop（**上游未提供许可证**）、
  Pocket-Poster（GPL-3.0）、forcequitOS（bad_query 研究）、opa334 / Dopamine（内核漏洞研究）。
- **结论：可以搬进我们的公开仓库**，但必须履行 GPL 义务：
  1. 保留 3105 的 `LICENSE` 与源码里的版权头（我们做到了：源码逐字节未改，`LICENSE` 已随包放在
     `Vendor/ThreeOneOSFive/LICENSE`）；
  2. 保留 `THIRD_PARTY_NOTICES.md`（同样随包保留）；
  3. **说明改动**：我们只新增了一个符号前缀头（见下），没有修改 3105 的任何源文件；
  4. 因为我们把它与 App 一起分发，**本 App 的再分发需按 GPL-3.0 的条款进行**（仓库已 public，
     源码可获取，符合要求）。
- 也就是说：**引入 3105 意味着本项目的再分发许可应按 GPL-3.0 对待**。如果你不希望承担 GPL 义务，
  唯一的选择是不搬它的代码（退回「只做模式外壳」），代价是这个模式不能真正工作。

## 五、附带 IPA 的观察

`3105-unsigned(1)(1).ipa`（3.13 MB）解包后是 `Payload/ThreeOneOSFive.app/`，
**没有内嵌 dylib**：漏洞与沙盒逃逸是**直接编进主二进制**的（`bad_query`、`kexploit_opa334` 等符号
都在 App 主可执行文件里），与它的工程结构一致（`exploit/`、`kexploit/` 都是 App target 的源文件）。

## 六、用法

1. 设置 → **内核模式**：选 `FilzaJailedDS 2.2`（默认）或 `3105`；
   - 每一行都会显示**适用范围**、你的设备/系统是否**在范围内**，以及一句推荐；
   - 如果所选模式不在范围内，激活前会给出橙色提示 + 一个「切换到另一个模式」按钮。
2. 回到「内核访问」→ 点**激活内核访问**（入口只有一个，内部按所选模式分派）。
3. 日志会写明用的是哪个模式、跑到哪一阶段：
   - 3105：`阶段 1/3：kexploit_opa334（内核读写）` → `阶段 2/3：proc_self` → `阶段 3/3：sandbox_escape`
     →（失败时）`阶段 3/3 回退：bad_query（MCM 沙盒扩展令牌）`；
   - 失败会给出**模式名 + 阶段 + 原因**，并写进 `Documents/Logs/kernel-breadcrumb.log`。
4. 切换模式后**需要重新激活**（两套后端各自独立，不会互相复用状态）。

## 七、隔离做法（为什么不会互相影响）

- **只做加法**：`FilzaTweak/**`、`kexploit_*`、`DSCredEscape*` 一行未改；默认模式的代码路径与 0.4.0 逐字一致。
- **唯一分派点**：`DSKernel.m` 的 `activateWithLog:` 里加了一个 `if (DS3105KernelSelected())` 分支，
  选中 3105 时直接返回、**绝不进入**下面 FilzaJailedDS 的逻辑；未选中时该条件恒为假。
- **符号隔离**：3105 自带一份与我们同名的 `kexploit_opa334` / `krw` / `offsets`，两者必须共存于同一个
  可执行文件，所以新增 `DS3105SymbolPrefix.h` 把 3105 侧 **179 个自有符号**统一改名为 `t3105_*`，
  并通过 XcodeGen 的 `compilerFlags: -include …` **只作用于 `Vendor/ThreeOneOSFive` 下的源文件**。
- **不共用原语**：`DS3105Kernel.m` 只调用 3105 自己的入口，不调用也不暴露我们的 `kread/kwrite`；
  它的就绪状态是自己的静态变量，与现有后端的 `gEscaped` 无关。
- **共用（有意为之）**：设置页 UI、激活入口的那一处分派、「沙盒外写探针」与
  `myfilza.fileSystemAccessChanged` 通知（这样替换页/应用管理器不必关心用的是哪个后端）。
- **头文件不串台**：3105 的目录**没有**加进 `HEADER_SEARCH_PATHS`（两套后端各有一份 `krw.h`/`offsets.h`，
  加进去就可能互相解析错）；3105 自己的源文件靠「同目录优先」解析自己的头，
  适配层 `DS3105Kernel.m` 则用显式相对路径包含 3105 的头。

## 八、已知边界

- 3105 的失败路径会调用它自己的 `kexploit_abort()`：在漏洞阶段内是 `longjmp` 回调用点
  （上游注释写明 "app stays alive"），只有漏洞阶段之外才会 `exit()`。**未修改**这个行为。
- 两个后端都不覆盖：`/System`、`/usr` 等 SSV 签名卷仍只读。
- 3105 声明支持的 27 beta 是按 **build 白名单**判定的（24A5355q / 24A5370h / 24A5380h / 24A5390f）；
  其它 27 build 不在其声明范围内（我们仍允许尝试，但会在日志里警告）。
